01Async questions: ask, keep going, answer later

ask_user_question gains async?: boolean. Async asks do not block the tool — the model keeps working, the question parks on a status board, and your answer is injected into the context whenever you get to it (follow-up mid-run, new turn when idle — even after a resume).
  • Same tool, one param. Description says: sync when unclear; specific skill workflows mandate async.
  • Summon: C-x q or /questions — the question session becomes the current input; the transcript keeps streaming above.
  • Persistence: pending questions are event-sourced entries; they re-appear on resume, branch-aware.
  • Unified with backlog/when_afk: one merged extension owns the board + the follow-up dispatcher.

Everything shown here was exercised end-to-end in a QEMU VM (tmux + scripted no-network model). Navigate with ← → or the dots. Two slides are interactive — they carry the open taste forks.

Pending asks are event-sourced (askq entries, the backlog pattern): queued / resolved, folded from the active branch. Undo/tree moves disarm questions that left the branch; drafts are persisted too (half-answer, sleep, resume — the draft is still in the editor).

  • Esc on the run aborts the run, not the question — pending stays valid; a late answer simply starts the next turn. No surprise turn is spawned on abort.
  • backlog / when_afk render on the same board (one merged extension). Deliveries share one dispatcher: sendUserMessage with followUp while a run is active.

09Open forks — recommendations
